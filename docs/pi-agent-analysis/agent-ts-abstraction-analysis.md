# Pi `agent.ts` 抽象分析

本文分析 `references/pi-mono/packages/agent/src/agent.ts`。该目录是只读参考项目；本文不改变 Pi 的实现，也不建议 ABook 直接复制其 TypeScript 代码。

Pi 的 `Agent` 不是模型提供商、工具集合或持久化会话本身。它是一个**单 Agent、内存态的运行协调器**：将低层的 `agentLoop` 包装成一个具有稳定状态、事件订阅、取消、消息队列和易用 API 的对象。

## 1. 顶层定位

Pi 的分层可以概括为：

```text
调用者 / UI / CLI
        |
        v
Agent (`agent.ts`)
  - 内存状态与公开 API
  - 事件订阅与状态归约
  - steering / follow-up 队列
  - 取消与生命周期
        |
        v
agentLoop (`agent-loop.ts`)
  - 请求模型
  - 解释模型 tool call
  - 校验并执行工具
  - 追加 tool result，决定下一轮
        |
        v
StreamFn / 模型适配层 (`pi-ai`)
```

因此，`Agent` 不直接实现模型的 ReAct 循环。模型输出工具调用、工具执行、工具结果回灌模型、继续下一轮的闭环由 `agentLoop` 实现；`Agent` 负责让这个循环在应用中可观察、可取消、不可重入，并保持内存中的对话状态一致。

## 2. 顶层接口与设计理由

### 2.1 `AgentOptions`

`AgentOptions` 是构造时依赖注入的边界，而不是一张无约束的配置表。它将依赖分为六类：

| 类别 | 接口字段 | 用途 | 设计收益 |
| --- | --- | --- | --- |
| 初始状态 | `initialState` | 注入系统提示词、模型、工具、历史 | 测试和恢复会话不依赖全局变量 |
| 上下文适配 | `convertToLlm`、`transformContext` | 将应用消息变为模型消息，或在发送前裁剪/注入 | 内部消息模型不被模型协议绑死 |
| 模型传输 | `streamFn`、`getApiKey`、`transport`、回调 | 提供流式调用与认证、请求观测 | Provider 可替换，令牌可动态刷新 |
| 工具治理 | `beforeToolCall`、`afterToolCall`、`toolExecution` | 拦截、审计、修改工具执行结果 | 权限和审计不污染每个工具实现 |
| 下一轮控制 | `prepareNextTurn`、`prepareNextTurnWithContext` | 在轮次边界更新上下文/模型/思考等级 | 允许外部根据结果改变下一轮配置 |
| 运行策略 | 队列模式、会话 ID、思考预算、重试上限 | 控制调度和 Provider 选项 | 运行策略与业务消息分离 |

`streamFn` 是唯一类型上必填的运行依赖。其它字段均有明确默认值或是可选扩展点。这避免 `Agent` 在构造或模块导入时绑定某个模型厂商、读取环境变量或访问网络。

### 2.2 `AgentState`

公开 `state` 聚合了两个不同生命周期的数据：

- 可由调用者配置的长期状态：`systemPrompt`、`model`、`thinkingLevel`、`tools`、`messages`。
- 只读的运行态：`isStreaming`、`streamingMessage`、`pendingToolCalls`、`errorMessage`。

这一划分很重要：调用者可以在空闲时替换模型和工具，但不应伪造“工具正在执行”或“当前流式消息”。内部实现用 `MutableAgentState` 仅在本模块内放宽只读约束，避免将运行态变成公共写入口。

`tools` 和 `messages` 的 setter 会复制顶层数组。这样调用方执行 `agent.state.tools = sourceTools` 后，若再修改 `sourceTools`，不会意外替换 Agent 的工具清单。它不深拷贝工具或消息对象，因此对象内部仍应被视为共享引用。

### 2.3 `AgentMessage`、`convertToLlm` 与 `transformContext`

Pi 允许 Agent 历史保存应用自定义消息，而 LLM 只能理解标准的 user/assistant/toolResult 消息。于是它将两个责任拆开：

```text
AgentMessage[]
  -> transformContext()    // 可选：裁剪、摘要注入、检索结果注入
  -> convertToLlm()        // 必须：过滤或映射到模型支持的 Message[]
  -> provider request
```

好处是 UI 通知、命令执行记录、压缩摘要等可以出现在完整 transcript 中，而无需污染模型协议。轻量 `Agent` 只提供钩子；会话树和自动压缩属于更高层的 `AgentHarness`。

### 2.4 `AgentEvent` 与订阅机制

循环不直接修改 UI。`agentLoop` 产生统一的生命周期事件，`Agent.processEvents()` 先把事件归约到 `state`，再按注册顺序 `await` 通知订阅者。

这样 UI 在收到 `message_update` 时，读取到的 `state.streamingMessage` 已经是同一事件对应的值；持久化订阅者也可在 `message_end` 时安全写入最终消息。代价是慢订阅者会延迟后续循环，这是一种刻意的背压和一致性取舍，不是高吞吐事件总线。

### 2.5 两类用户消息队列

Pi 区分：

- `steer()`：当前 assistant turn 和其工具全部完成后、下一轮模型请求前插入。适合“改做这个”。
- `followUp()`：仅当没有工具调用且没有 steering 消息时插入。适合“完成后再做这个”。

队列模式可为 `all` 或 `one-at-a-time`。默认后者，避免一次性把很多异步用户输入塞进同一轮上下文，仍保留按顺序逐项处理的交互感。

### 2.6 运行生命周期

`ActiveRun` 把 Promise、resolve 函数和 `AbortController` 绑定为一次运行的唯一所有权：

- `activeRun` 存在即禁止第二次 `prompt()` / `continue()`，防止两个循环同时篡改同一 transcript。
- `abort()` 通过标准 `AbortSignal` 向模型请求和工具传递取消。
- `waitForIdle()` 等待的不只是循环结束，还包括所有 `agent_end` 订阅者结束。

这对 CLI 特别实用：取消和退出不会留下半更新的 UI 状态或未完成的会话写入。

## 3. 一次调用的控制流

```text
prompt(input)
  -> normalizePromptInput()
  -> runWithLifecycle()
       -> createContextSnapshot() + createLoopConfig()
       -> runAgentLoop()
            -> processEvents(event)
                 -> 先更新 Agent.state
                 -> 再依次 await listeners
       -> 失败时合成标准 assistant error 消息和结束事件
       -> finishRun() 清理运行态、唤醒 waitForIdle()
```

注意两个边界：

1. `createContextSnapshot()` 对数组作浅复制，保证本轮开始时看到稳定的消息、工具清单；消息对象本身不是深复制。
2. `prepareNextTurn` 可以在循环轮次之间返回新的 context/model/thinking level。因此同一 `prompt()` 的后续模型请求不必与第一轮完全相同。

## 4. 与 `AgentHarness` 的关系

`Agent` 与 `AgentHarness` 都建立在 `agentLoop`、`AgentContext`、`AgentTool`、`AgentEvent` 上，但两者不是父子组合关系。`AgentHarness` 不持有这个 `Agent` 类，而是直接调用低层循环，并增加：会话树、JSONL/SQLite 存储、分支导航、上下文压缩、技能和工具环境。

所以 ABook 若只需要内存态问答和工具调用，可借鉴 `Agent` 的边界；若要持久多轮会话或上下文压缩，应分别设计存储与上下文投影层，而不是把它们塞进 CLI。

## 6. 可借鉴与不应照搬之处

对 ABook，最值得借鉴的是：

1. 将循环执行器与状态外观分开：PydanticAI Agent/运行调用与 CLI 状态、消息历史不应耦在同一函数中。
2. 为工具调用设计显式的事件和权限 hook；写入知识库的工具尤其需要在 hook 或工具边界做用户授权检查。
3. 让多轮历史成为显式参数或明确状态，而不是隐藏全局变量。
4. 使用单运行锁和取消信号，避免同一对话同时触发两次工具写入。

不应直接照搬的是 Pi 的 TypeScript 类型和复杂会话能力。ABook 当前规模可保留 PydanticAI 的依赖注入与 Pydantic 验证，在需求真正出现后，再以 Python 的 `dataclass`/Pydantic 模型、事件回调和独立存储层实现相同的职责分离。
